Turn one service manifest into a running local stack.

TDK reads simple service definitions, generates the local development machinery, wires dependencies, and validates the result before the team starts coding.

What TDK makes visible instead of leaving teams to guess.

Project control plane

TDK creates the project manifest and stack-wide Tilt configuration. The output is inspectable, local, and versionable.

$ tdk project --yes created .tdk/project.json generated .tdk/.tdk-out/Tiltfile

Resource scaffolding

Each service gets a manifest, Dockerfile, package defaults, TypeScript config, source entry, and a test shell.

$ tdk resource api --type backend --stack pre-alpha generated service.json, Dockerfile, package.json, tests

Dependency graph

api declares internalDependencies, so the local stack knows that database comes first.

Docker Compose path

Try the workflow in a container before installing anything permanently on the host.

Validation proof

tdk project --check and tdk status --verbose verify the generated project.
